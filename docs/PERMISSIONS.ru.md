# Права и модель доступа

## Внутренний superadmin

Superadmin — **флаг записи User в UltraPermissions**. Узла прав `ultrapermissions.admin` для GUI здесь нет. Сам по себе OP или `*` не заменяет этот флаг при открытии `/uperms` и проверке административных веток `/upc`.

- Выдать: консоль `upc AddSuperAdmin <User>`.
- Снять: `upc RemoveSuperAdmin <User>`.
- Снять у всех: `upc PurgeSuperAdmins`.

GUI требует игрока с текущим флагом; консоль работает через `/upc`. При отзыве роли существующая сессия GUI/чата больше не может менять права. Административные ветки команд также проверяют роль заново.

## Доступные узлы прав

| Узел | Назначение |
|---|---|
| `ultrapermissions.commands.promote` | Доступ к `/promote <User> <GroupPath>` |
| `ultrapermissions.commands.demote` | Доступ к `/demote <User> <GroupPath>` |

Другие административные операции используют внутренний флаг superadmin. Эти две команды проходят обычную проверку прав Bukkit; правила OP и значений по умолчанию зависят от конфигурации сервера и плагина. Не следует предполагать существование дополнительных узлов `ultrapermissions.*` для административных действий.

## Делегирование групп

В GUI группы можно настроить разрешённые к выдаче группы и максимальный срок выдачи (grant groups). Пользователь с такой действующей группой получает ограниченный доступ к `/upc`:

- `AddGroup` — только разрешённые группы и допустимый срок.
- `listGroupPermissions`, `listPlayerPermissions` — просмотр списков.

Делегирование не даёт редактор GUI, создание пользователей, изменение суффиксов или прочие административные операции. Они требуют superadmin. Неизвестному пользователю доступ закрывается без исключения.

## Вычисление прав

Права назначаются пользователям и группам, могут наследоваться и ограничиваться миром/сервером/временем. `example.node` — разрешение, `-example.node` — запрет. Шаблоны прав, приоритет групп, персональные права, правила Bukkit по умолчанию/OP и настройка переопределения запретов участвуют в проверке. При конфликте проверяйте результат в журнале прав, не делайте вывод только по одному шаблону.

Консоль и доверенные плагины с доступом к API являются административной границей доверия. Общий HMAC-ключ кластера означает доверие всем его держателям. Игроки не должны иметь доступа к учётной записи MySQL и файлам Registry/mysql.properties/security.properties.
