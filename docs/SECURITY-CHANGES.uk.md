# Зміни безпеки

## Мережеві межі

1. **H-01 — керування непідписаними повідомленнями.** Старий формат більше не приймається. Використовується окремий канал із HMAC-SHA256, realm, відправником/одержувачем, напрямком, часовою позначкою та nonce. Повторні/прострочені пакети відхиляються; діють обмеження розміру й частоти. `restart`/`update` заборонені навіть у підписаному повідомленні.
2. **H-02 — облікові дані в каналі гравця.** Паролі MySQL не передаються через повідомлення плагінів. Кожен вузол налаштовується локально. Вхідний пакет не може замінити стан MySQL.
3. **H-03 — SQL-ін'єкція синхронізації.** Значення SELECT/INSERT/UPDATE/DELETE зв'язуються як параметри, моделі/ключі перевіряються, ідентифікатори таблиць обмежено. Через старий допоміжний метод не можна передати готовий виконуваний SQL.

## Надійність і привілеї

4. **M-01 — неперевірені виконувані завантаження.** Мережеве встановлення редактора та завантаження JAR оновлень вимкнено. Перевірений JAR установлюється вручну; в активних шляхах встановлення/оновлення немає loadPlugin із мережевої відповіді.
5. **M-02 — вичерпання пулу/потоків.** Прибрано цикли активного очікування та створення потоку на кожній ітерації. Для пулу/SQL задано час очікування; синхронізацію обмежено 64 завданнями, повторні сповіщення об'єднуються.
6. **M-03 — застаріла авторизація GUI.** Поточна роль перевіряється перед дією, інвентар прив'язується до сеансу; відкликання superadmin припиняє дії. Введення з чату переноситься до планувальника сервера й перевіряється повторно.
7. **M-04 — десеріалізація предметів Java.** Нові дані — обмежений JSON із префіксом UPI1. Старий формат допускає лише дозволені контейнери/псевдоніми Bukkit із фільтром розмірів, глибини, посилань і класів. Довільні класи та недозволені зареєстровані псевдоніми відхиляються.
8. **M-05 — транспорт MySQL.** За замовчуванням TLS увімкнено, незашифровані віддалені підключення заборонено. Потрібен VERIFY_IDENTITY; драйвер без підтримки відхиляється до передавання облікових даних. Явний ssl=false дозволено лише для точних localhost/127.0.0.1.

## Додатково перед випуском

Для адміністративних гілок `/upc` запроваджено спільну вимогу superadmin; винятки — обмежений AddGroup і перегляд списків прав. Закрито гілки зміни суфіксів без цієї вимоги й обмежено RegisterUser. Невідомий користувач отримує відмову без винятку Optional. Виправлено підпис рядкового аргументу, розбір true/false і відповіді консолі через CommandSender замість nullable Player. Дистрибутив не містить персонального ID покупця та спільного вбудованого токена API оновлень. Перевірку ліцензії збережено.

## Що перевіряє CI та що залишається поза ним

CI запускає негативні перевірки на тестових підмінах Bukkit/JDBC і структурно перевіряє кінцевий JAR. Конкретні сервери, сертифікати/драйвери БД, мережевий екран/пересилання, усі варіанти CraftMeta та ігрове середовище потребують окремого тестового встановлення. Стандартна стара піктограма проходить перевірку міграції; непідтримувані старі компоненти відхиляються з помилкою, а не виконуються.

Зауваження LOW про синхронне визначення зовнішньої IP-адреси через HTTP та інформаційні зауваження щодо середовища не входили до цих восьми виправлень. Вбудовані бібліотеки перелічено окремо; відсутність повідомлення про вразливість версії не доводить відсутності невідомих помилок. Це супровід безпеки без обіцянки «усі експлойти усунуто» і без твердження про виявлені/видалені віруси.

Починаючи з 5.6.9, окрема перевірка CI також запускає Paper 26.2 на Java 25 і виконує 12 перевірок під час виконання. Точні межі та неперевірені сценарії описано в [документі про сумісність](COMPATIBILITY.uk.md). Стабільний випуск вимагає успішного збирання на обох ОС і цієї перевірки на сервері.
