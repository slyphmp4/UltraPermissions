# UltraPermissions 5.6.17 — update settings

Settings → Customisation now has one **Update Settings** entry. Its native TechsCode subview contains the two existing independent switches and one informational status item, plus the usual Back button. The switches retain their icons, text, colors and behavior. Unrelated controls keep their slots.

The status shows the installed and known latest versions, checking/downloading, an available update, a current version, a prepared restart, missing releases and errors. Opening the view requests one asynchronous check using the existing cache and rate limits. With both switches off, it checks metadata only, without enabling preferences or downloading a JAR. GUI redraws perform no network requests. Clicking the status item has no action.

Existing configuration, permission data, commands and integrations need no migration. Downloads still require a verified stable GitHub Release and apply only on a manual restart. The production artifact remains **UltraPermissions.jar**. No dependencies were added or upgraded.

The verification gates cover offline state/cancellation/control regressions, EN/RU/UK item metadata on real Paper, Linux/Windows builds, reproducibility, persistence and synthetic load. Connected-client visual clicking and Cardboard/Fabric rendering still require manual verification.
