# UltraPermissions 5.6.13 — independent update notifications and automatic GitHub downloads

A focused follow-up to [5.6.12](https://github.com/slyphmp4/UltraPermissions/releases/tag/v5.6.12). This release preserves the original TechsCode GUI, existing commands, permission nodes and data formats.

## New updater preferences

- **Settings → Customisation** now has four evenly spaced, original-style controls: Prefix, Update Chat Notifications, Ingame Updater, and GUI Update Interval. TechsCode's item icons, animated gold/yellow titles, click descriptions, and navigation are retained.
- **Update Chat Notifications:** enables or disables status messages to current superadmins. With automatic downloads disabled, an available newer stable GitHub Release is still reported with a Releases link; no JAR is downloaded.
- **Ingame Updater:** independently enables or disables automatic download of a **published stable release** from [slyphmp4/UltraPermissions](https://github.com/slyphmp4/UltraPermissions/releases). With chat notices disabled, the verified JAR is still downloaded and staged without an in-game chat announcement.
- Both preferences disabled means no automatic update checks or chat notices. Both enabled means both features work. RU/UK translations cover every new item title, state, action and status message, reaching **835 registered keys in each locale**.
- Preferences survive a server restart. Older appearance settings keep their existing `updaterEnabled` value as the initial state of **both** switches, avoiding unexpected downloads or messages for users who previously disabled the updater.

## Update safety

- Only the same verified GitHub Release asset path and SHA-256 checks as 5.6.12 are used. Existing JAR backups, native Bukkit staging, non-overwrite protection and cancellation of in-flight downloads remain in place.
- A downloaded plugin is **not hot-loaded** and the server is **not automatically restarted**. Installation takes effect on the **next manual server restart**.
- A GitHub-provided SHA-256 digest is an integrity check, not an independent publisher signature.

## Verification and limitations

- **PASS (GitHub CI):** Ubuntu and Windows JDK 21 builds, identical production JARs, **459 security/regression assertions in 20 groups**, complete RU/UK bundle and placeholder validation.
- **PASS (GitHub CI):** isolated Paper 26.2 / Java 25, two full boots, persistence and 29 runtime assertions; synthetic 512-profile / 400,000-permission-check performance test (not 512 connected Minecraft clients).
- **NOT RUN:** manual in-game clicking of the four updated settings buttons on a connected client; actual live 5.6.12 → 5.6.13 auto-download and restart handover; older Spigot/Paper, Cardboard, Bungee/Waterfall, database outage/recovery and large real-player concurrency. These are not certified by this CI run.

## Installation and rollback

1. Stop the server and back up the previous UltraPermissions JAR, plugin data folder and external database (if any).
2. Install **UltraPermissions-5.6.13.jar** from this release (not the sources JAR or project ZIP). Remove duplicate older JARs from `plugins/`.
3. Start the server and review both updater settings in **Settings → Customisation**. Back up again before deploying in production.
4. If your 5.6.12 installation has auto-updating enabled, it should stage 5.6.13 automatically once GitHub publishes its verified JAR; a manual restart is still required. This exact transition has not been live-tested.
5. For rollback, stop the server and restore **both** the previous JAR **and** matching data backups.
