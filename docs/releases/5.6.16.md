# UltraPermissions 5.6.16 — stable player heads

This update addresses rapidly flickering player-head textures in the TechsCode editor. The original GUI layout, slots, icons, text animations, commands, translations and stored data formats remain unchanged.

## Fixes

- Head profiles now have a deterministic identity derived from the texture URL instead of a new random UUID on every GUI redraw. A changed skin URL produces a different profile without altering any stored user record.
- A bounded cache reuses at most 1,024 head profiles. Modern Bukkit player profiles use the public texture-copy operation; the legacy authlib fallback remains for older implementations.
- Inventory slots are written only when their item changes. The forced inventory refresh is no longer scheduled on completely unchanged frames. Existing animated text and the intentional rotating head on the Overview Users button remain active.

## Verification and limits

The release gates check Linux/Windows builds, component and security regressions, localization, reproducibility, Paper 26.2 runtime behavior and synthetic performance. New checks cover head UUID stability, cache reuse/eviction and real Paper skull metadata with unchanged and changed skin URLs. A connected client and Cardboard/Fabric rendering still require manual visual confirmation; this test suite does not claim to simulate client texture rendering.

## Install / rollback

Stop the server, back up the current JAR, `plugins/UltraPermissions/` and any database, install **UltraPermissions.jar**, and restart. Existing configuration and permission data need no migration. The updater stages a verified release for the next manual restart. See [configuration](../CONFIGURATION.md) and [compatibility](../COMPATIBILITY.md).
