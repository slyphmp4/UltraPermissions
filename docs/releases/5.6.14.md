# UltraPermissions 5.6.14 — auto-updater diagnostics and compatibility fix

A focused follow-up to [5.6.13](https://github.com/slyphmp4/UltraPermissions/releases/tag/v5.6.13). The original TechsCode menus, icons, layout, commands, permissions, settings and storage formats are unchanged.

## Fixes

- An updater failure now states the affected stage in the server console: missing verified GitHub asset, HTTP response, update directory, conflicting staged file, size, SHA-256, plugin.yml identity or backup. Signed download URLs and credentials are not logged.
- Recoverable GitHub asset network failures and HTTP 5xx responses are retried at most three times, with a small delay. HTTP 403/429 and validation failures do not trigger repeated downloads.
- When a Bukkit-compatible loader exposes a remapped/cache JAR outside `plugins/`, the updater can use the **unique** installed UltraPermissions JAR with matching `plugin.yml` name and version in `plugins/`. Missing or duplicate candidates fail closed; it never guesses a target.
- The release plugin filename is now **UltraPermissions.jar**, with no version in the name. The plugin's internal version is still 5.6.14. The original installed JAR filename is preserved when staging a native Bukkit update.
- Added negative regression checks for remapped paths, ambiguous copies, precise digest diagnostics and GitHub redirect-host validation. The isolated Paper two-boot test additionally checks native `plugins/update` handover across restart.

## Safety and limitations

- GitHub Releases remains the only update source; the downloaded executable must match the release-provided SHA-256 and expected `plugin.yml` identity. No hot-loading, forced restart or overwrite of another staged JAR.
- GitHub's SHA-256 is an integrity check, not an independent publisher signature.
- A running 5.6.12/5.6.13 installation with the previous downloader bug may **not be able to update itself**. If it fails, manually install `UltraPermissions.jar` once.
- **Verification:** CI outcomes must be read from the associated PR/run before merging. The real Cardboard 26.2.24 automatic download and subsequent restart are **not certified** by the Paper test; manual validation on a backup server remains necessary.

## Installation and recovery

1. Stop the server and back up the previous JAR, `plugins/UltraPermissions/` and external database (if used).
2. Remove duplicate older UltraPermissions plugin JARs, then install **UltraPermissions.jar** from this release in `plugins/`. Do not install the sources JAR or project ZIP.
3. Start the server and verify both update switches in **Settings → Customisation**. If an update fails, inspect the detailed console reason; do not delete unrelated files in `plugins/update` blindly.
4. Automatic downloads are staged for the **next manual restart**. If the server loader does not support native Bukkit update-folder handover, install the verified JAR manually.
5. Rollback requires stopping the server and restoring the previous JAR and matching data backup.
