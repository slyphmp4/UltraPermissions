# UltraPermissions 5.6.13 — незалежні сповіщення й автоматичні оновлення

Невелике доповнення до [5.6.12](https://github.com/slyphmp4/UltraPermissions/releases/tag/v5.6.12). Оригінальний GUI TechsCode, команди, вузли дозволів та формати зберігання даних не змінено.

## Нові налаштування оновлень

- У розділі **«Налаштування → Персоналізація»** тепер чотири рівномірно розміщені кнопки: префікс, сповіщення про оновлення, оновлювач у грі та інтервал оновлення GUI. Збережено оригінальні предмети, золотисто-жовту анімацію назв, підказки й навігацію TechsCode.
- **Сповіщення в чаті** незалежно вмикають або вимикають повідомлення для суперадміністраторів. Коли автозавантаження вимкнене, новий стабільний випуск із GitHub Releases усе одно відображається в чаті з посиланням, але JAR не завантажується.
- **Оновлювач у грі** незалежно керує автоматичним завантаженням **опублікованих стабільних випусків** з [основного репозиторію](https://github.com/slyphmp4/UltraPermissions/releases). Коли сповіщення вимкнені, перевірений JAR і далі завантажується й готується до встановлення без повідомлень гравцеві.
- Якщо обидва перемикачі вимкнені, немає ані перевірок, ані повідомлень; якщо обидва ввімкнені — працюють обидві функції. Усі нові назви, стани й повідомлення локалізовано українською та російською: по **835 зареєстрованих ключів**.
- Налаштування зберігаються після перезапуску. Під час перенесення зі старого формату **обидва** параметри спочатку успадковують попереднє значення `updaterEnabled`, тому раніше вимкнена функція не увімкнеться несподівано.

## Безпека оновлення

- Збережено перевірку SHA-256 випуску GitHub, резервну копію попереднього JAR, стандартну теку оновлень Bukkit, захист від перезаписування та скасування незавершених завантажень.
- **Гарячого завантаження й примусового перезапуску немає.** Зміни застосовуються **лише після наступного ручного перезапуску сервера**.
- SHA-256 з метаданих GitHub перевіряє цілісність, але не є незалежним цифровим підписом розробника.

## Результати перевірок та обмеження

- **PASS (GitHub CI):** збірки Ubuntu/Windows на JDK 21, побайтово однакові JAR, **459 перевірок безпеки й регресій у 20 групах**, повні українська та російська локалізації.
- **PASS (GitHub CI):** Paper 26.2 / Java 25, два повні запуски, збереження даних і 29 перевірок на сервері; синтетичне навантаження 512 профілів і 400 000 перевірок дозволів (це не 512 під’єднаних гравців).
- **НЕ ПЕРЕВІРЕНО:** ручне натискання чотирьох кнопок у клієнті Minecraft, фактичне автоматичне завантаження/встановлення 5.6.12 → 5.6.13, старі версії Spigot/Paper, Cardboard, Bungee/Waterfall, збої MySQL та великий онлайн справжніх гравців. CI не гарантує сумісність із цими сценаріями.

## Установлення та відкат

1. Вимкніть сервер і зробіть резервну копію попереднього JAR, даних UltraPermissions і бази даних, якщо використовується.
2. Установіть **UltraPermissions-5.6.13.jar** із випуску, прибравши дублікати старих JAR із `plugins/`. Не встановлюйте JAR вихідного коду або ZIP проєкту.
3. Запустіть сервер і перевірте обидва перемикачі в розділі «Налаштування → Персоналізація».
4. Якщо автозавантаження було ввімкнене в 5.6.12, після публікації перевіреного JAR версія 5.6.13 має підготуватися автоматично, але для застосування потрібен ручний рестарт. Реальний перехід іще не перевіряли.
5. Для відкату відновіть **і попередній JAR, і відповідну резервну копію даних** на вимкненому сервері.
