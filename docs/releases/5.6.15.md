# UltraPermissions 5.6.15 — permissions integrity and maintenance

This release fixes the four regressions identified in the 5.6.14 audit and refreshes the build/runtime dependencies. The TechsCode GUI, commands, permission nodes and existing data formats are preserved.

## Administrator-visible fixes

- `/promote` and `/demote` determine the current rank separately for each invocation. A previous user's group cannot be reused for a different user or rank path.
- Prefixes, suffixes and other persisted values now preserve changes that differ only in letter case, including full-cache synchronization.
- Rejected/pending logins no longer retain player sessions or create account records. Existing users keep early permission checks; new accounts are registered on a successful join.
- **If a configured MySQL store cannot be opened, the server/proxy stops with an actionable console message. It never switches to older local permission files.** Invalid initial storage is also rejected. Fix database access, TLS/driver or damaged data and restart; do not erase the configuration to bypass the error.
- A single local-key refresh reads only that record. MySQL reads stream rows and reject a single result exceeding 64 MiB of encoded values, preserving existing data on failure.
- Removed purchaser-identifying metadata, obsolete service-provider descriptors and unnecessary rank-path logging.

## Dependency and build updates

Gradle 8.14.6 fixes the published Gradle daemon-channel advisories. Gson 2.15.0, HikariCP 7.1.0, NBT API 2.16.1, Commons Codec/IO/Lang/Logging, SLF4J and bStats are refreshed with pinned sources and SHA-256. Normal builds remain offline. The unchanged Apache HTTP 4.x and unknown-version internal Kyori/JetBrains subsets remain documented; no unverified major platform migration is implied.

## Verification and limits

The release gates require Windows/Linux builds, negative security regressions, 7085 API contracts, byte-for-byte archive reproducibility, localization checks, a real Paper 26.2 / Java 25 persistence/update-handover test and a configured-MySQL failure boot. The Paper load gate still measures synthetic profiles rather than connected clients. Check the release's attached verification report for the exact artifact hash and results.

Persistence writes still acknowledge completion after the write; they can block on slow storage. This release bounds reads and fixes correctness without introducing an asynchronous write-behind/data-migration contract. Real MySQL TLS negotiation, all optional plugin combinations, BungeeCord and older-server matrices are not exhaustively verified.

## Install / rollback

Stop the server, back up the existing JAR, `plugins/UltraPermissions/` and the database, then install **UltraPermissions.jar** and restart. The existing automatic updater stages this file for the next manual restart. For rollback, stop the server and restore the matching JAR/data backup. See [configuration](../CONFIGURATION.md), [compatibility](../COMPATIBILITY.md) and [component provenance](../../THIRD-PARTY.md).
