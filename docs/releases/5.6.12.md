# UltraPermissions 5.6.12 — stabilization, full RU/UK localization and automatic updates

Community maintenance release of the original TechsCode UltraPermissions plugin, maintained by slyphmp4. This update unifies the nine hardening stages and the Vault correction. It preserves the original TechsCode GUI design, command names, permission nodes and storage formats.

## Lifecycle, permissions and data protection

- Hardened startup/shutdown, error handling, task cancellation, thread confinement and state synchronization. Removed the obsolete Spigot Premium entitlement network request that could prevent an open-source build from starting.
- Protected local data writes, failure reporting and recovery paths, and verified group, user and permission persistence across a complete Paper restart.
- Corrected Vault `groupHas` checks with world/server scope handling, and tightened authorization, network boundaries and input validation.
- Reduced repeated permission work, bounded caches and permission logs, and avoided unnecessary repeated updater operations. No intentional GUI redesign.

## Russian and Ukrainian

- Reviewed GUI titles, item descriptions, command output, errors, settings, time formats, migration messages and updater status in both interfaces.
- Bundled **826 registered translation keys in each language** (Russian and Ukrainian), with color codes, substitutions and locale resources checked by CI.
- The server owner reported successful interactive GUI, command and language tests for both locales. Minecraft item labels supplied by the client and text from external plugins depend on their own localization.

## In-game updater

- With `IngameUpdater` enabled, a newer **published stable release** from [slyphmp4/UltraPermissions Releases](https://github.com/slyphmp4/UltraPermissions/releases) is downloaded automatically; prereleases, drafts and unrelated repositories are ignored.
- The updater validates the downloadable JAR, size and GitHub-provided SHA-256 digest; it backs up the existing file and stages the new JAR under Bukkit's native update directory using the original filename.
- The staged file takes effect only on the **next manual server restart**. No forced restart or remote code execution is performed. Up-to-date, unavailable-network and download-failure feedback is localized.
- **Important:** a SHA-256 digest from GitHub release metadata is not an independent publisher signature. A real live upgrade from 5.6.12 to a later published version remains to be tested.

## Verification

- **PASS:** Linux and Windows Java 21 builds; byte-identical production JAR; **453 security/regression assertions in 20 groups**; complete packaged RU/UK locale checks.
- **PASS:** isolated actual **Paper 26.2 / Java 25**, two full server boots with preserved storage and **29 runtime assertions**, including commands, permissions, item codecs and translation loading.
- **PASS:** CI-only real-Paper load test with **512 synthetic identities, 400,000 measured permission checks and 16 data writes**; about 24,995 checks/second, TPS 19.89 and heavy tick p95 50.05 ms under a two-CPU container limit. These profiles are **not connected Minecraft clients**.
- **Owner-reported PASS:** server launch/shutdown, commands, all tested RU/UK GUI screens, group/permission changes, data persistence, plugin integrations if installed, updater no-update/network-error handling and stability with actual players.
- **NOT RUN:** older Spigot/Paper and Cardboard, Bungee/Waterfall, real MySQL failure/recovery, large concurrent player/network/world load, and actual download/handover of a newer stable release. These configurations are not certified by this test matrix.

## Installation and rollback

1. Stop the server and back up its existing UltraPermissions JAR, plugin data folder and any external database.
2. Download **UltraPermissions-5.6.12.jar** from this release. Do not install the sources JAR or the Gradle project archive.
3. Remove duplicate older UltraPermissions plugin JARs from `plugins/`, install the new JAR and start the server.
4. Confirm that groups, permissions, RU/UK settings and optional integrations still work. The updater never restarts the server for you.
5. To roll back, stop the server and restore both your previous JAR **and** matching data backups.

See the [compatibility matrix](../COMPATIBILITY.md), [security changes](../SECURITY-CHANGES.md) and [repository quality gate](https://github.com/slyphmp4/UltraPermissions/issues/6).
