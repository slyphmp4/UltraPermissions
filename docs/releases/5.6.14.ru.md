# UltraPermissions 5.6.14 — диагностика и совместимость автообновления

Исправление после [5.6.13](https://github.com/slyphmp4/UltraPermissions/releases/tag/v5.6.13). Оригинальный GUI TechsCode, иконки, расположение кнопок, команды, права, настройки и форматы данных не менялись.

## Исправления

- Вместо общего сообщения об ошибке консоль указывает этап: отсутствие проверенного файла в GitHub Releases, HTTP-ответ, папка обновлений, конфликт с другим JAR, размер, SHA-256, неверный `plugin.yml` или резервное копирование. Секреты и подписанные ссылки не попадают в журнал.
- Временные сетевые ошибки и HTTP 5xx при скачивании допускают не более трёх попыток с небольшой задержкой. HTTP 403/429 и ошибки проверки не вызывают многократных скачиваний.
- Если Bukkit-совместимый загрузчик показывает кешированный JAR вне `plugins/`, обновлятор может найти **единственный** установленный JAR UltraPermissions с соответствующими названием и версией в `plugin.yml`. При отсутствии файла или наличии дубликатов обновление безопасно прекращается.
- Файл плагина в релизе называется **UltraPermissions.jar** без номера версии. Внутренняя версия — 5.6.14. При подготовке обновления сохраняется имя уже установленного JAR, как требует механизм Bukkit.
- Добавлены регрессионные проверки путей кеширующего загрузчика, дубликатов, диагностики SHA-256 и доверенных переадресаций GitHub. Двухэтапный тест Paper проверяет замену JAR через `plugins/update` при перезапуске.

## Безопасность и ограничения

- Источник обновлений — только GitHub Releases. Обязательны SHA-256 и правильный `plugin.yml`. Нет горячей загрузки, принудительного рестарта или перезаписи чужого подготовленного JAR.
- SHA-256 от GitHub подтверждает целостность, но не является независимой подписью автора.
- Если в работающей 5.6.12/5.6.13 сломан прежний обновлятор, **самостоятельно до 5.6.14 она может не обновиться**. Тогда один раз установите JAR вручную.
- **Проверки:** перед слиянием нужно смотреть реальные результаты CI в PR. Автоскачивание и применение обновления на Cardboard 26.2.24 **не подтверждены** тестом Paper; необходима ручная проверка на резервном сервере.

## Установка и откат

1. Остановите сервер и сохраните копии прежнего JAR, `plugins/UltraPermissions/` и внешней базы данных, если она есть.
2. Удалите дублирующиеся старые JAR UltraPermissions и установите **UltraPermissions.jar** из релиза в `plugins/`. JAR исходников и ZIP проекта не нужны.
3. Запустите сервер и проверьте оба переключателя в «Настройки → Персонализация». При ошибке посмотрите конкретную причину в консоли; не удаляйте посторонние файлы из `plugins/update` вслепую.
4. Автозагрузка подготавливает файл **к следующему ручному перезапуску**. Если загрузчик сервера не поддерживает стандартную обработку папки обновлений Bukkit, установите проверенный JAR вручную.
5. Для отката остановите сервер и восстановите предыдущий JAR и соответствующую резервную копию данных.
