# UltraPermissions 5.6.14 — діагностика та сумісність автооновлення

Виправлення після [5.6.13](https://github.com/slyphmp4/UltraPermissions/releases/tag/v5.6.13). Оригінальний GUI TechsCode, іконки, розміщення кнопок, команди, дозволи, налаштування й формати даних не змінювалися.

## Виправлення

- Замість загальної помилки консоль показує етап збою: відсутній перевірений файл у GitHub Releases, HTTP-відповідь, тека оновлень, конфлікт з іншим JAR, розмір, SHA-256, неправильний `plugin.yml` або резервне копіювання. Секрети та підписані посилання не потрапляють до журналу.
- Тимчасові мережеві помилки та HTTP 5xx під час завантаження допускають щонайбільше три спроби з короткою затримкою. HTTP 403/429 та помилки перевірки не спричиняють повторних завантажень.
- Якщо Bukkit-сумісний завантажувач показує кешований JAR поза `plugins/`, оновлювач може знайти **єдиний** установлений JAR UltraPermissions із відповідною назвою та версією у `plugin.yml`. Коли файлу немає або є дублікати, оновлення безпечно припиняється.
- Файл плагіна у випуску має назву **UltraPermissions.jar** без номера версії. Внутрішня версія — 5.6.14. Під час підготовки оновлення зберігається назва вже встановленого JAR, як вимагає Bukkit.
- Додано регресійні перевірки шляхів кешувального завантажувача, дублікатів, діагностики SHA-256 і довірених переадресацій GitHub. Двоетапний тест Paper перевіряє заміну JAR через `plugins/update` після перезапуску.

## Безпека й обмеження

- Джерело оновлень — лише GitHub Releases. Обов'язкові SHA-256 і правильний `plugin.yml`. Немає гарячого завантаження, примусового перезапуску чи перезапису чужого підготовленого JAR.
- SHA-256 від GitHub перевіряє цілісність, але не є незалежним підписом автора.
- Якщо у запущеній 5.6.12/5.6.13 зламаний попередній оновлювач, **самостійно до 5.6.14 вона може не оновитися**. Тоді встановіть JAR вручну один раз.
- **Перевірки:** до злиття потрібно переглянути фактичні результати CI у PR. Автозавантаження та застосування оновлення на Cardboard 26.2.24 **не підтверджені** тестом Paper; потрібна ручна перевірка на резервному сервері.

## Установлення та відкат

1. Зупиніть сервер і збережіть копії попереднього JAR, `plugins/UltraPermissions/` і зовнішньої бази даних, якщо вона є.
2. Видаліть дублікати старих JAR UltraPermissions та встановіть **UltraPermissions.jar** із випуску до `plugins/`. JAR вихідного коду й ZIP проєкту не потрібні.
3. Запустіть сервер і перевірте обидва перемикачі в «Налаштування → Персоналізація». У разі збою перегляньте точну причину в консолі; не видаляйте сторонні файли з `plugins/update` навмання.
4. Автозавантаження готує файл **до наступного ручного перезапуску**. Якщо завантажувач не підтримує стандартне застосування оновлень Bukkit, установіть перевірений JAR вручну.
5. Для відкату зупиніть сервер і відновіть попередній JAR та відповідну резервну копію даних.
