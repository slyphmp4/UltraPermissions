# Изменения безопасности

## Сетевые границы

1. **H-01 — управление неподписанными сообщениями.** Старый формат больше не принимается. Используется отдельный канал с HMAC-SHA256, realm, отправителем/получателем, направлением, временной меткой и nonce. Повторные/просроченные пакеты отклоняются; есть ограничения размера и частоты. `restart`/`update` запрещены даже в подписанном сообщении.
2. **H-02 — учётные данные в канале игрока.** Пароли MySQL не передаются через сообщения плагинов. Каждый узел настраивается локально. Входящий пакет не может заменить состояние MySQL.
3. **H-03 — SQL-инъекция синхронизации.** Значения SELECT/INSERT/UPDATE/DELETE связываются как параметры, модели/ключи проверяются, идентификаторы таблиц ограничены. Через старый вспомогательный метод нельзя передать готовый исполняемый SQL.

## Надёжность и привилегии

4. **M-01 — непроверенные исполняемые загрузки.** Сетевая установка редактора и скачивание JAR обновлений отключены. Проверенный JAR устанавливается вручную; в активных путях установки/обновления нет loadPlugin из сетевого ответа.
5. **M-02 — исчерпание пула/потоков.** Убраны циклы активного ожидания и создание потока на каждой итерации. Для пула/SQL задано время ожидания; синхронизация ограничена 64 работами, повторные уведомления объединяются.
6. **M-03 — устаревшая авторизация GUI.** Текущая роль проверяется перед действием, инвентарь привязывается к сессии; отзыв superadmin прекращает действия. Ввод из чата переносится в планировщик сервера и проверяется повторно.
7. **M-04 — десериализация предметов Java.** Новые данные — ограниченный JSON с префиксом UPI1. Старый формат допускает только разрешённые контейнеры/псевдонимы Bukkit с фильтром размеров, глубины, ссылок и классов. Произвольные классы и неразрешённые зарегистрированные псевдонимы отклоняются.
8. **M-05 — транспорт MySQL.** По умолчанию TLS включён, незашифрованные удалённые подключения запрещены. Требуется VERIFY_IDENTITY; драйвер без поддержки отклоняется до отправки учётных данных. Явный ssl=false разрешён только для точных localhost/127.0.0.1.

## Дополнительно перед выпуском

Для административных веток `/upc` введено общее требование superadmin; исключения — ограниченный AddGroup и просмотр списков прав. Закрыты ветки изменения суффиксов без этого требования и ограничен RegisterUser. Неизвестный пользователь получает отказ без исключения Optional. Исправлены подпись строкового аргумента, разбор true/false и отправка ответов консоли через CommandSender вместо nullable Player. В поставке нет персонального ID покупателя и общего встроенного токена API обновлений. Лицензионная проверка сохранена.

## Что проверяет CI и что остаётся вне него

CI запускает отрицательные проверки на тестовых подменах Bukkit/JDBC и структурно проверяет конечный JAR. Конкретные серверы, сертификаты/драйверы БД, межсетевой экран/пересылка, все варианты CraftMeta и игровое окружение требуют отдельной тестовой установки. Стандартная старая иконка проходит проверку миграции; неподдерживаемые старые компоненты отклоняются с ошибкой, а не выполняются.

Замечание LOW о синхронном определении внешнего IP через HTTP и информационные замечания по окружению не входили в эти восемь исправлений. Встроенные библиотеки перечислены отдельно; отсутствие сообщения об уязвимости версии не доказывает отсутствие неизвестных ошибок. Это сопровождение безопасности без обещания «все эксплойты устранены» и без утверждения об обнаруженных/удалённых вирусах.

Начиная с 5.6.9, отдельная проверка CI также запускает Paper 26.2 на Java 25 и выполняет 12 проверок во время выполнения. Точные границы и непроверенные сценарии описаны в [документе о совместимости](COMPATIBILITY.ru.md). Стабильный выпуск требует успешных сборок на обеих ОС и этой проверки на сервере.
