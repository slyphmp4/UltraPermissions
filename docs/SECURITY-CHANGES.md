# Изменения безопасности

## Сетевые границы

1. **H-01 — неподписанное управление.** Старый формат больше не принимается. Используется отдельный канал с HMAC-SHA256, realm, sender/recipient, направлением, timestamp и nonce. Повторные/просроченные пакеты отклоняются; есть ограничения размера и частоты. `restart`/`update` запрещены даже в подписанном сообщении.
2. **H-02 — credentials в player transport.** Пароли MySQL не передаются через plugin messaging. На каждом узле реквизиты задаются локально. Входящий пакет не может заменить MySQL state.
3. **H-03 — SQL-инъекция синхронизации.** Значения SELECT/INSERT/UPDATE/DELETE связываются параметрами, модели/ключи проверяются, идентификатор таблицы ограничен. Нельзя передать готовый SQL через legacy helper.

## Надёжность и привилегии

4. **M-01 — непроверенный исполняемый download.** Установка редактора и скачивание update JAR из сети отключены. Проверенный JAR устанавливается вручную; сетевого loadPlugin нет в активных installer/update путях.
5. **M-02 — pool/thread exhaustion.** Убраны циклы активного ожидания и создание потока на каждую итерацию. Пул/SQL имеют timeout; sync ограничен 64 работами, повторные уведомления объединяются.
6. **M-03 — устаревшая GUI-авторизация.** Текущая роль проверяется перед действием, инвентарь привязывается к сессии; отзыв superadmin прекращает действия. Chat input переносится на server scheduler и проверяется повторно.
7. **M-04 — Java item deserialization.** Новые данные — bounded JSON с префиксом UPI1. Старый формат читает только разрешённые контейнеры/алиасы Bukkit с фильтром размеров, глубины, ссылок и классов. Произвольные классы и registered aliases не исполняются.
8. **M-05 — транспорт MySQL.** По умолчанию TLS включён, для удалённой БД plaintext запрещён. Требуется VERIFY_IDENTITY; драйвер без поддержки отклоняется до отправки credentials. Исключение ssl=false — только точные localhost/127.0.0.1 при явной настройке.

## Дополнительно перед выпуском

Для административных веток `/upc` введено общее требование superadmin; исключения — ограниченный AddGroup и просмотр списков прав. Закрыты ветки изменения суффиксов без этого требования и ограничен RegisterUser. Неизвестный пользователь получает отказ без Optional exception. Исправлены подпись строкового аргумента, разбор true/false и отправка ответов консоли через CommandSender вместо nullable Player. В поставке нет персонального purchaser ID и общего встроенного update API token. Лицензионная проверка сохранена.

## Что проверено и что остаётся вне CI

В CI запускаются отрицательные проверки на тестовых Bukkit/JDBC объектах и структурная проверка конечного JAR. Конкретные серверы, сертификаты/драйверы БД, firewall/forwarding, все варианты CraftMeta и игровой runtime требуют отдельной тестовой установки. Стандартная legacy-иконка проходит проверку миграции; неподдерживаемые старые компоненты отклоняются с ошибкой, а не выполняются.

LOW-замечание о синхронном HTTP определении внешнего IP и informational замечания по окружению не входили в эти восемь исправлений. Встроенные библиотеки перечислены отдельно; отсутствие advisory для версии не доказывает отсутствие неизвестных ошибок. Это security maintenance, без обещания «все эксплойты устранены» и без утверждения об обнаруженных/удалённых вирусах.
