# Права та модель доступу

## Внутрішній superadmin

Superadmin — **прапорець запису User в UltraPermissions**. Вузла прав `ultrapermissions.admin` для GUI тут немає. Статус OP або `*` самі по собі не замінюють цей прапорець під час відкриття `/uperms` і перевірки адміністративних гілок `/upc`.

- Надати: консоль `upc AddSuperAdmin <User>`.
- Зняти: `upc RemoveSuperAdmin <User>`.
- Зняти в усіх: `upc PurgeSuperAdmins`.

GUI вимагає гравця з чинним прапорцем; адміністрування з консолі відбувається через `/upc`. Після відкликання ролі наявний сеанс GUI/чату більше не може змінювати права. Адміністративні гілки команд також перевіряють роль повторно.

## Наявні вузли прав

| Вузол | Призначення |
|---|---|
| `ultrapermissions.commands.promote` | Доступ до `/promote <User> <GroupPath>` |
| `ultrapermissions.commands.demote` | Доступ до `/demote <User> <GroupPath>` |

Інші адміністративні операції використовують внутрішній прапорець superadmin. Ці дві команди проходять звичайну перевірку прав Bukkit; правила OP і значень за замовчуванням залежать від конфігурації сервера та плагіна. Не припускайте наявності додаткових вузлів `ultrapermissions.*` для адміністративних дій.

## Делегування груп

У графічному редакторі групи можна налаштувати дозволені для надання групи та максимальний строк їх надання (grant groups). Користувач із такою активною групою отримує обмежений доступ до `/upc`:

- `AddGroup` — лише дозволені групи та допустимий строк.
- `listGroupPermissions`, `listPlayerPermissions` — перегляд списків.

Делегування не надає редактор GUI, створення користувачів, зміну суфіксів чи інші адміністративні операції. Для них потрібен superadmin. Невідомому користувачу доступ закривається без винятку.

## Обчислення прав

Права призначаються користувачам і групам, можуть успадковуватися та обмежуватися світом/сервером/часом. `example.node` — дозвіл, `-example.node` — заборона. Шаблони прав, пріоритет груп, особисті права, правила Bukkit за замовчуванням/OP і налаштування перевизначення заборон беруть участь у перевірці. У разі конфлікту перевіряйте результат у журналі прав, не робіть висновок лише за одним шаблоном.

Консоль і довірені плагіни з доступом до API утворюють адміністративну межу довіри. Спільний HMAC-ключ кластера означає довіру до всіх його власників. Гравці не повинні мати доступу до облікового запису MySQL і файлів Registry/mysql.properties/security.properties.
